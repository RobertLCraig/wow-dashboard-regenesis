# Trial pipeline: its own view, or a flag on the roster row

## What I need from you
Pick 1 or 2. It decides whether the roster grows a second page, and it needs you because the input
is how many trials the guild actually runs at once and whether anyone other than you would use it.

## Why
This has been an open planning question since April, sitting under "Tier 3, defer or revisit". It
stays open because both answers are reasonable and neither has a technical argument that settles
it, which is exactly the sort of question that expires by being ignored rather than answered.

## Options
1. **A flag on the existing roster row.** Trial status becomes a value on the member, filterable
   with the existing filter chips. Cost: no pipeline history, so "who did we trial last tier and
   what happened" is not answerable.
2. **A dedicated pipeline view** with the stages apply, trial, raider, bench, alumni. Cost: a
   second page to maintain, a state machine to keep honest, and it is dead weight if the guild
   trials two people a tier.

## Recommendation
Option 1. The roster page already has filters, search and sortable columns, so a trial flag is
close to free and lands as a filter chip beside the ones officers already use. The history that
option 2 buys is the only real difference, and the Recent Activity log already records changes, so
some of it exists.

Option 2 becomes right if recruitment gets busy enough that several people are mid-trial at once
and officers need to see where each one is without asking. That is a volume question and you are
the only one who can answer it.
